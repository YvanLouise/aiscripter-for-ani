# 外部 AI 创作与续改规范

本文件是交给 Codex、Claude Code、Cursor 等**外部编程代理**的工作约定，适用于 AIScripter for ani 当前源码版 `0.1.0`。软件本身不调用 AI 模型，也不会自动把工程或提示词发给外部服务。原生工程使用 [v2](project-format-v2.zh-CN.md)，TypeScript 程序场景使用 [v3 与 SDK](project-format-v3.zh-CN.md)；字段以对应 Schema 与实际校验为准。

若已连接[本机 MCP](mcp-local.zh-CN.md)，优先读取当前编辑器草稿，使用 `stage_changes` → `commit_changes` 提交，再用 `render_frames`、`get_diagnostics`、`export_preview` 查看效果。MCP 可看见未保存的人工修改，脚本与结构变更共同进入编辑器撤销。仅在未使用 MCP 时直接修改磁盘，并遵守下方外部文件冲突规则。

## 1. 接受任务前

1. 先确认软件版本、目标工程目录和 `project.json.formatVersion`。原生新工程用 v2；需要类型化程序场景时明确采用 v3。现有 v1 工程先阅读[v1 规范](project-format-v1.md)及[v2 升级说明](project-format-v2.zh-CN.md#1-工程目录与版本)。
2. 阅读本文件、对应版本工程规范和 Schema，再查看与任务相近的合法示例。若无法获取必要文档，先向用户索取，不能凭通用视频软件或 JavaScript 经验猜字段。
3. 明确交付画幅、工程 fps、总时长、场景顺序、所需素材、可编辑范围和需要保留的人工修改。缺少非关键偏好时可采用合理默认值，并在交付时说明；不要臆造本软件未实现的功能。
4. 对已有工程，先通过 MCP 读取**当前草稿**及磁盘修订，记录稳定 ID 和基线；不要以旧磁盘内容覆盖未保存草稿。直接修改磁盘时，先确认用户已保存或明确选择版本。

## 2. 新建工程

1. 创建 `project.json`、`scenes/`、`scripts/`、`assets/`。工程 ID、场景 ID、图层 ID、音轨/音频片段 ID 使用稳定且不重复的值；名称应说明用途，例如 `Main Title`、`Product Model`、`Background Particles`。
2. 先用软件原生的文字、图形、图片、视频、音频及 3D 图层。普通标题必须仍是 `text`，可编辑图形仍是 `shape`。仅把原生图层无法表达的效果放在 `custom` 模块。
3. 把相机位置、效果强度、速度、颜色等用户可能修改的值公开为 `params` 或图层属性，并用关键帧/表达式连接时间。不要把整个影片预渲染成一段不可编辑视频来代替工程。
4. 所有动画时间使用整数帧，按场景局部时间写图层与关键帧，按全局时间写 `audioTracks`。片段入点包含、出点不包含。复制或分割场景时生成新的场景和图层 ID；资源文件可共享。
5. 将依赖文件放进工程内并使用 `/` 相对路径。脚本只能读项目内文件；不能依赖网络、Node.js 或系统命令。选择素材时注意目标机器的 Chromium 视频编解码与 WebGL2 支持。当前字体通过系统 `fontFamily` 使用，不能假设随工程自动打包字体。
6. 运行工程检查，然后在 AIScripter 中打开、预览至少起点/接缝/终点，抽查动态参数与自定义脚本，导出短片段验证。

推荐先复制 `examples/sequence-v2/` 的目录结构，再替换工程 ID、场景、内容与素材。不要原样复用示例的 ID 作为多个新对象的 ID。

## 3. 续改现有工程

续改必须以**当前工程状态**为输入：连接编辑器时包含未保存草稿；离线时为磁盘版本。用户的移动、文字、关键帧、排序、裁剪、锁定和上一轮 AI 修改都属于现状。仅修改点名对象和必要依赖：

| 用户要求 | 建议修改范围 | 应保留 |
| --- | --- | --- |
| “只改背景效果” | 背景图层参数或脚本，必要的背景资源 | 标题、其他图层、场景顺序、人工关键帧 |
| “延长第二个场景” | 该场景 `clip` 或 `durationFrames` 与必要图层时长 | 全局音轨原有 `startFrame` |
| “替换产品图片” | 对应图层 `asset` 及新素材 | 图层 ID、变换、关键帧、其他资源 |
| “复制片段并分别调整” | 新场景 JSON、清单引用、新场景和图层 ID | 原片段与共享素材 |

编辑过程：

1. 读取并记录当前值及文件修订基线；确认目标对象的 ID，不靠数组位置猜测。
2. 生成最小变更。对已有对象保留 ID 和未要求修改的字段；不要格式化重写不相关的场景与脚本。新增对象使用新 ID。
3. 修改前检查用户是否锁定对象。锁定不是文件系统权限，但表示人工不希望误改；若请求与锁定冲突，应指出目标而不是悄悄解锁。
4. 对比修改前后，确认只触及约定范围。MCP stage 携带预期草稿和磁盘修订，确认差异后 commit。修订冲突时重新读取与 stage。直接写磁盘时使用完整合法 JSON 和临时替换，避免半写文件。
5. 执行校验、打开预览。若编辑器同时显示“本地未保存改动与外部修改冲突”，按用户选择重载或另存本地副本；**没有自动合并**。

## 4. 程序化动画的交付规则

v3 推荐采用 TypeScript `defineScene(create)`、项目内组件和 SDK 直接求值。稳定对象 ID、显式种子、初始化资源与乱序重复帧检查是交付要求。MCP 修改后先 `build_project`，再渲染。SDK 1.1.0 支持程序对象画布编辑、公开参数与实例参数关键帧；人工记录保存在 `program.edits`，AI 更新代码时应保持对象 ID 和记录。MCP 自动保留未携带的 edits，拒绝替换已有人工记录及可能影响锁定项的共享代码修改。对象缺失或类型变化会保留覆盖并提示，不能保证任意重命名后自动绑定。检查 `render_frames` 的 programEdit 反馈，完整接口见 [v3](project-format-v3.zh-CN.md)、[第三轮编辑规范](ai-creation-phase-3.zh-CN.md)和 `examples/program-scenes/`。

- `custom` 图层的 `.mjs` 必须导出 `render`，可导出 `setup`。`setup.readProjectFile()` 只读工程内文件；导入模块也必须在工程内。
- 画面应由 `frame`、`timeSeconds`、`params`、固定 `seed` 和项目资源决定。同一工程修订的同一帧重复渲染应一致。不要依赖跨帧可变状态、计时器、网络响应或真实时钟。
- WebGL2 脚本明确设置视口并绘制完整一帧。对 Canvas 2D 与 WebGL2 分别使用 `ctx` 或 `gl`，不要假设两者同时存在。
- 公开参数的名字应易懂，并保留默认值。若算法内部无法可视化编辑，至少让图层能在编辑器中移动、缩放、改变透明度、时间范围及公开参数。
- 脚本错误只会使该层报错，但交付前仍须逐帧抽查或导出测试；不能把“工程能加载”当作效果已正确。

## 5. 检查与交付

在 AIScripter 源码目录执行：

```powershell
npm run validate:project -- "D:\path\to\project" --strict-assets
```

随后在软件中执行 **工程菜单 → 检查工程**。结构检查必须通过；资源警告须修复或明确说明。再预览并导出一段短片，核对画面、音频与时间映射。目录应包含所有必需素材，不依赖工程外绝对路径。

交付回复应列出：工程入口 `project.json` 的位置、格式版本和画幅/fps、场景与总帧数、主要可编辑图层和公开参数、增加或修改的文件、校验/预览/导出结果、仍需用户注意的字体或编解码限制。若是续改，再列出**被保留的人工修改**和精确变更范围。不要声称检查工具能证明 AI 已阅读过文档；它只能验证工程的部分结构与资源。

## 6. 可复制给外部 AI 的任务模板

### 创建工程

```text
请先阅读 AIScripter for ani 源码目录中的 docs/README.md、
docs/external-ai-workflow.zh-CN.md、docs/project-format-v2.zh-CN.md，
并核对 schema/project.schema.json 和 schema/scene.schema.json。
请在 <目标目录> 创建 v2 动画工程：<描述场景、时长、画幅、fps、素材>。
优先保持标题、图形、图片和关键帧可编辑；复杂效果使用 custom 图层并公开参数。
完成后运行 npm run validate:project -- "<目标目录>" --strict-assets，
在 AIScripter 预览并导出短片段，报告工程路径、帧数、可编辑参数和验证结果。
```

### 修改已有工程

```text
请先阅读 AIScripter 当前项目文档，再读取 <工程目录> 中当前的
project.json、引用场景及相关脚本。只修改 <目标场景/图层 ID> 的 <具体内容>。
保留其他图层、人工调整、关键帧、锁定状态、片段顺序和全局音轨位置。
修改前后给出文件与对象级差异；运行工程检查并预览相关帧。
如果当前工程存在未保存编辑或外部修改冲突，先说明冲突，不要覆盖。
```

模板中的尖括号由用户替换。外部 AI 应根据具体任务决定编辑范围，不能把模板当成免读工程文档的替代品。
